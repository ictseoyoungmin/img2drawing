# img2drawing v1.0.2

v1.0.2 promotes the locally validated exact incremental timelapse engine to the default
`DrawingSession.export_timelapse()` execution backend for supported stroke histories. The public
session method signature is preserved from v1.0.1; backend selection is internal, and the v1.0.1
canonical exporter and P9 renderer remain intact as a whole-export fail-closed fallback.

## Default timelapse backend

The normal session export route now selects the local-first fast engine when the history is
eligible and FFmpeg is available:

- monotone forward history replay;
- content-addressed persistent stroke-patch caching;
- edit-aware dirty-region recomposition;
- dirty-region Lanczos resampling;
- atomic lossless delta-frame pack staging;
- persistent palette caching;
- FFmpeg Bayer palette use with `diff_mode=rectangle`.

Unsupported actions, raw ordered spatial erasers, or an unavailable FFmpeg backend cause the entire
session export to fall back to the canonical implementation rather than mixing execution semantics
inside one replay. Advanced/debug callers can still invoke the vNext output-layer exporter with an
explicit canonical backend; this control is intentionally not added to the normal session method.

Full PNG frame spooling is no longer required by the fast backend. The lossless delta pack is
disposable staging authority and frame PNG materialization remains an explicit output-layer option
for downstream workflows that require it.

## RenderProfile authority correction

The fast renderer consumes `RenderProfile.paper_tooth`, `paper_scale`, and `paper_seed` directly.
It no longer lets session metadata defaults override the persisted render profile. The independent
final render uses the same prepared RenderProfile state, and fast final output is required to match
that canonical final RGB exactly before the export is accepted.

## Compatibility and safety

- persisted drawing/session schemas are unchanged;
- package-root exports remain unchanged;
- the public `DrawingSession.export_timelapse()` signature is unchanged;
- `img2drawing.provenance.export_fast_timelapse()` remains available as a specialized API;
- fill/region actions and unsupported semantics use whole-export canonical fallback;
- persistent caches remain disposable optimization state and are never source of truth;
- delta packs are written through partial files and atomically promoted on completion;
- post-v1.0.1 S09 streaming production code and its active CI test are retired from the active tree and retained only as legacy evidence.

The fast GIF route uses constant FPS timing. Canonical fallback retains the legacy variable-duration
frame policy. Fast GIF color tolerance is validated against an independently rendered canonical
final PNG; the lossless frame state itself must be RGB pixel-exact.

## Validation

R8 default-backend focused regression passes on both source and an installed wheel. A final
minimal-session-signature rehearsal also passed the same 16 focused tests while preserving the
v1.0.1 session method byte-for-byte. The installed module import sweep covers 106/106 modules.
The prior real-session integration run for the 1,272-action window-study confirmed the normal
session API selected the fast backend, reused 1227/1227 persistent patches on warm replay, and
produced an RGB pixel-exact final frame against the bound RenderProfile. Performance remains
environment-sensitive and is reported as cold/warm evidence, not as a semantic compatibility
guarantee.

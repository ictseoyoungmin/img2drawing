# img2drawing v1.0.1

v1.0.1 is a bounded Astra-derived authoring patch over the v1.0.0 stable baseline. It copies no
subject-specific answer geometry. Instead, it turns repeated friction from the successful explicit-
stroke run into general-purpose authoring mechanics and guidance.

## What changed

### Geometry-preserving stroke retuning

`img2drawing.vnext.retune_stroke()` lets a worker correct width, pressure, opacity, graphite grade,
taper, grain, or other supported tool parameters without re-authoring an already-correct path.

The helper resolves the current replacement descendant and preserves:

- exact current points;
- stable stroke identity;
- role and semantic part;
- confidence and layer;
- explicitly authored pressure;
- existing provenance metadata such as control-point/interpolation notes when present.

Derived pressure is regenerated when material parameters change, so a taper/pressure correction can
actually affect the rendered result. The helper emits the existing `replace_stroke` history action;
there is no new persistence action or schema.

This directly addresses the strongest code-level signal from the Astra run: 111 of its 120 stroke
replacements were intended as material-only continuity/taper corrections, and resubmitting geometry
manually could silently change smooth authored paths.

### Shared Catmull-Rom curve sampling

`img2drawing.vnext.sample_catmull_rom()` provides deterministic Catmull-Rom sampling with
approximate arc-length spacing. Workers no longer need to recreate task-local spline math simply to
author a smooth observed interval.

The sampler is an authoring utility, not geometry authority. Real cusps, corners, tangency breaks,
component joins, insertions, folded edges, or other topology changes must be split and authored
explicitly rather than smoothed through.

### Continuous-edge pencil

`continuous_pencil` keeps the `form_pencil` material family but uses very low endpoint taper so
separate strokes that belong to a genuinely continuous observed boundary do not appear prematurely
cut at their joins.

`form_pencil` defaults are unchanged. The new preset is general-purpose and is not tied to
mechanical subjects.

### Authoring and correction guidance

The instruction graph now makes several successful-worker habits explicit without creating stages:

- related marks are authored/reviewed as a **semantic group** that answers one coherent visual or
  structural question rather than an arbitrary stroke count;
- correction first distinguishes a **geometry residual** from a **material residual**;
- correct geometry is preserved for material-only fixes;
- smoothness follows observed topology rather than an unconditional preference for splines;
- fresh whole-drawing renders remain the authority after each meaningful correction.

## What did not change

- no subject-specific Astra coordinates, scripts, control-point tables, or answer image were copied
  into the skill;
- no new runtime stage or lifecycle was added;
- no automatic artistic-quality or likeness score was added;
- no model-specific execution path was added;
- persisted session/action schemas are unchanged;
- the canonical `DrawingSession` member set is unchanged;
- the canonical package-root API remains narrow and unchanged;
- the canonical `RenderProfile` is unchanged;
- R23 checkpoint compatibility is unchanged.

The specialized `img2drawing.vnext` namespace adds `retune_stroke` and `sample_catmull_rom`, and the
tool preset registry adds `continuous_pencil`.

## Evidence boundary

The source evidence remains the curated GPT-6 Astra v1.0.0 demonstration:

- 490 total actions
- 358 stroke additions
- 120 replacements
- 12 deletions
- 0 fill actions
- 124-frame canonical end-to-end replay, every 4 actions, cursor 0 → 490
- canonical final PNG exactly equal to replay final PNG
- canonical GIF final-frame maximum channel error: 1

The real comparison image and canonical replay GIF remain in the v1.0.0 showcase entry. v1.0.1
uses only generalized lessons from that run; the demonstrated geometry is not a worker input.

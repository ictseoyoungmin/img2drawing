# img2drawing v1.5.0

Release date: 2026-11-28
Release scope: **Optional layered editing and exchange**
Default renderer: **img2drawing-pencil / 11**

The source selects v1.5.0 for publication after successful main CI. The actual GitHub Release,
tag target and assets establish publication; the mutable status page records that observation.

## Choose the working structure the drawing needs

Ordinary line art and hand-drawn studies continue through the existing `DrawingSession`
without enabling layers. The same session can optionally use named paint layers and
isolated groups, visibility, inherited content locks, whole-layer opacity, ordering,
membership changes and an active paint layer. Layer operations are retained in the same
action history and native checkpoint as the marks.

Explicit conversion puts an existing drawing into one neutral paint layer in its original
render order. It preserves the old pixels without rewriting authored IDs, geometry, numeric
material layers or graphite seeds. Resume never silently converts a session. Splitting or
reordering the drawing afterward is a compositing edit, and can change integer alpha rounding.

## Shared native editing

One guarded proposal can transform graphite paths, ink paths, solid areas and screentones.
The caller chooses whether to preserve or scale line widths, and whether a tone pattern stays
fixed to the page or follows the object. Preview and apply bind the same action contents,
cursor, drawing state and render profile; an invalid, stale or locked member rejects the
whole application rather than leaving a partially modified selection.

Paths and object-following dot patterns support nonsingular similarity transforms. Areas and
page-fixed tone selections can also use nonsingular affine transforms. Authored path erasers
must be re-authored explicitly; the common transform helper does not infer their intended
effect. Erasers lift earlier graphite only in their own paint layer; white ink remains paint.

Public undo/redo moves the existing history cursor and saves the checkpoint atomically. A
mixed proposal still contains individual history actions; use its action count to undo or
redo the complete proposal. Observations, inspections and intent are retained, and a branch
that would orphan retained audit evidence is rejected.

## Layer delivery and native continuation

`export_layer_pngs` and `export_openraster` provide transparent paint-layer images with names,
order, visibility, opacity and isolated group hierarchy. Hidden content is retained. Raw
layer images do not bake opacity that the receiving document will apply again.

The output also contains an exact canonical merged image and a fidelity manifest. Separately
downsampled layers can differ when recomposited; the manifest reports the difference using
the runtime compositor. An external application's rounding or color handling can differ
further. Canonical merged-image identity is not a claim of universal external flattening parity.

Native checkpoints and retained inspection evidence are included by default, so continued
stroke editing does not depend on the old output folder. A reference-bound checkpoint still
needs its original reference. Keep the checkpoint and its evidence folder together when
relocating a delivery; `include_native=False` explicitly selects raster-only handoff.

Points, pressure, tools, procedural tone parameters and replay belong to the native session.
Edits made to raster layers in another application are not imported as original native marks.

## Compatibility and scope

- Default pencil v11, normalized graphite v1/v2/v3, and mixed-media v1/v2/v3 material profiles
  keep their established identities and renderer contract digests.
- Nontrivial layer composition has its own `normal-isolated-rgba8-v1` document contract.
  The initial mode is Normal with isolated groups and opacity applied once to a completed node.
- Layered histories use canonical timelapse rendering, with the same document composition as
  preview, inspection and final PNG. No new layered Fast-path performance claim is made.
- Document dimensions, composition work, hierarchy and simultaneous surfaces have bounded
  budgets. This release does not promise arbitrary page size, layer depth or realtime editing.
- Additional blend modes are follow-up work. PSD output, raster import, masks, pass-through
  groups and a visual layer editor are outside this initial scope.
- Existing development metadata and historical release manifests, tags and freezes remain
  unchanged. Private references, drawing coordinates and large generated outputs are not
  included in the runtime package or repository evidence.

## Actual Krita continuation and measured limits

Actual Krita 5.2.9 opened the final ORA through its `kritarunner` executable and official
document API. All 23 raster layers retain exact raw pixels; hierarchy, order, names, visibility,
locks and isolation match. Real rename, hide, group-opacity and translation edits were asserted
to take effect. Baseline and edited KRA save/reopen preserve the tested tree, raw layers and
displayed pixels exactly. GUI interaction was not tested.

Fractional input opacities are quantized to Krita's 8-bit values. The five measured imports
match `floor(255 * opacity)`. Krita's own ORA save/reopen further changes 150→149, 178→177
and 224→223 on three layers; other non-opacity fields and raw paint pixels remain exact.
A separate synthetic group also measures 127→126. No export compensation is applied.

The largest point differences occur at gutters and balloon/line boundaries, but repeated tone
differences also cause mild broad brightening across sky, ground and architecture. The largest
32×32 block mean brightness difference is 5.076 levels; this must not be described as an edge-only
effect. No missing panel, displaced figure or broad tonal inversion was observed. All 46 tracked
input/evidence files remained unchanged. These are version- and artwork-specific measurements.

Keep the canonical PNG and native session for exact native appearance. Use KRA for continued
work in the tested Krita environment while retaining the original ORA. KRA preserves the
imported state, including initial opacity quantization; it does not restore native stroke geometry
or the original decimal opacity. The exchange check establishes editable continuation with
stated limits, not universal pixel or professional-print fidelity.

# img2drawing v1.0.3rc2 candidate notes

Package identity: **1.0.3rc2**  
Public contract identity: `DrawingSession/1.0.3-vnext`  
Release revision: **A12**  
State: **unpublished release candidate**

`1.0.3rc2` is a focused follow-up to the rc1 renderer/markmaking candidate. It does not change the v10 renderer or fast-timelapse implementation measured for rc1 promotion. It aligns the user-facing gesture mode with the public runtime and hardens gesture construction against the opposite failure of smooth generic blobs.

## Why rc2 exists

G01 dogfood on rc1 exposed two reusable defects:

1. `DrawingIntent(drawing_mode="gesture")` raised `ValueError` even though the skill defines gesture drawing as a user-facing mode with pure and constructive finish levels.
2. Guidance that correctly rejected faceted ribcage/pelvis shorthand could still be satisfied by smooth bean/oval/capsule masses. Those marks were organic-looking but insufficiently specific to the observed subject.

The rc1 dogfood was therefore reopened rather than promoted directly to stable v1.0.3.

## Runtime alignment

- `gesture` is now a supported public `DrawingIntent.drawing_mode` value.
- `resolve_mode_guide("gesture")` exposes whole-pose, head-facing, mass-specificity, limb/support, and completion guidance through the ordinary public intent surface.
- Gesture remains a selection, **not** a workflow stage. Pure vs constructive is still a user-facing instruction-graph finish-level decision: explicit quick/pure requests select pure gesture, while unqualified `gesture drawing` defaults to constructive gesture.
- Checkpoint/resume preserves the gesture intent like other drawing modes.

## Gesture shape-language hardening

The instruction graph now rejects both sides of the abstraction failure:

- hard generic symbols such as orientationless circle-heads, faceted shields, boxes, triangles, and plates;
- smooth generic symbols such as beans, eggs, ovals, and capsules that erase observable facing, asymmetry, taper, or attachment relations.

Sparse gesture should preserve the few relations that make the current subject specific when visible: head profile/jaw/nape direction, shoulder/back/side transitions, torso taper, hip shelf, near/far exposure, leg-attachment spacing/direction, major limb chains, support, and decisive negative spaces/prop anchors.

Reference-supported roundness remains valid. The runtime/skill should not invent angular corners merely to prove a rounded bob, ribcage envelope, or hip/shorts silhouette is not a primitive. The failure condition is loss of structural information, not roundness itself.

## Markmaking adapter boundary

G01 also exposed a public-discovery trap. Semantic preset IDs such as `gesture-flow`,
`contour-weighted`, and `broad-graphite` are resolved markmaking vocabulary and are not necessarily
literal `DrawingSession.draw(tool=...)` values.

Workers should resolve them through the public API and pass the resolved kwargs:

```python
from img2drawing.vnext import resolve_mark_for_intent

mark = resolve_mark_for_intent(
    session.intent,
    "gesture",
    tool_preset="gesture-flow",
)
session.draw(points, part="dominant-action", **mark.draw_kwargs())
```

The rc2 regression surface guards this semantic-preset → runtime-tool adapter without exposing
private renderer names.

## G01 same-reference verdict

The same reference was rerun through separate pure and constructive gesture session histories. The
correction loop explicitly rejected intermediate outputs that still read as coarse polyline
construction, orientationless circle-head shorthand, closed pelvis capsules, or generic mannequin
masses.

The reviewed final pass preserved head facing, shoulder/torso direction, both major arm and leg
chains, support, rifle overlap, hip-to-leg attachment, and a stronger constructive near/far read
without invented faceting.

**G01 target failure class: PASS / CLOSED.** This is a bounded behavior verdict, not a claim of
production croquis quality or cross-agent/cross-subject generalization. Artifact hashes and the
correction record are in `dev/dogfood/g01-gesture-rc2/README.md`.

## Renderer/timelapse boundary

The rc2 slice does not modify the renderer/timelapse implementation paths covered by the rc1 promotion record. The existing same-environment width×3 v9/v10 benchmark and canonical↔fast pixel-exact results therefore remain authoritative for that subsystem:

- v10 cold render+pack vs v9: **+4.886%**;
- v10 warm render+pack vs v9: **+1.365%**;
- v10 cold patch-build vs v9: **+12.058%**;
- v9 fast = canonical RGB: **pixel-exact**;
- v10 fast = canonical RGB: **pixel-exact**.

Authority remains `dev/release/vnext/V1_0_3_RC1_PROMOTION.{md,json}` unless one of its measured implementation paths changes.

## Known quality blocker before stable promotion

A separate broad-pencil material defect remains open. At larger stroke widths, graphite/tooth feel
can become too weak and the stroke can read as a uniform digital ribbon; terminals can also appear
blunt or square. This renderer/material-quality issue is independent of G01 and should be closed
before deciding stable v1.0.3 readiness.

## Promotion boundary

This file is not a publication record. There is no `v1.0.3rc2` publish manifest, and **v1.0.2 remains the latest published stable release**.

Stable promotion requires the broad-pencil quality gate, the normal mechanical/package gates, and a
separate explicit stable freeze/publish manifest.

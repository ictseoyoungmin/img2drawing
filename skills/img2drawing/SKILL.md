# img2drawing

## Mission
Draw from references with explicit strokes. The worker/Agent is the semantic authority. CV/evidence tools may help the worker see, but may not decide pose, anatomy, or artistic correctness.

## Fresh-worker guarantee
A competent worker who receives only:
- this skill,
- the subject reference,
- the requested drawing mode,

must be able to continue the job without the user teaching the workflow pass by pass.

**Do not stop after a routine pass to ask "continue?" or "is this okay?".**
Self-observe, draw, render, compare, revise and advance autonomously.
Ask the user only if the source is missing/unreadable, the target itself is ambiguous, or two user requirements genuinely conflict.

## Authority model
`DrawingRun` is the only orchestration authority.
- `core/`: strokes, actions, history, session.
- `observation/`: agent-authored semantic observations and the immutable pre-draw observation lock.
- `stages/`: stage intent and expert drawing guidance, never semantic judgement.
- `review/`: artifact-bound dual-reference review and autonomous worker packet.
- `canvas/`: inspect and edit the current drawing.
- `render/`: pencil material only.
- `provenance/`: replay and timelapse.

## Required reading route
For a full-body croquis job:
1. Read `SKILL.md`.
2. Read `playbooks/autonomous-stage-hardening.md`.
3. Read `playbooks/full-body-croquis.md`.
4. Read `playbooks/subject-only-stage-derivation.md` unless explicit same-subject stage targets were supplied.
5. Read only the current stage reference in `references/stages/`.
6. Use the `worker_packet.md` generated by `prepare_stage_review()` for each pass.

Do not preload every anatomy/reference document. Pull extra references only when a concrete uncertainty requires them.

## Dual-reference rule
Every stage review distinguishes:
1. **Subject reference** — pose, proportion, overlap, perspective and weight truth.
2. **Stage exemplar** — abstraction, stroke vocabulary, line hierarchy and detail-budget guidance.
3. **Current drawing** — the exact artifact being judged.

Never copy pose or coordinates from a stage exemplar.

## Default stage progression
`P1_gesture → P2_primary_axes → P3_primary_masses → P4_structural_connections → P5_clean_blockin`

Do not sweep through them in one pass. Harden the current stage before moving on.

## Autonomous hardening loop
For every stage:

`read stage brief → observe subject whole → lock pre-draw view observation → draw bounded strokes → prepare_stage_review() → inspect mandatory views/crops → write concrete findings → revise highest-impact issues → fresh review → advance`

`prepare_stage_review()` writes both `worker_packet.json` and `worker_packet.md`. Those packets contain:
- stage intent;
- what to observe/draw/avoid;
- mandatory review questions;
- advance guidance;
- review artifact paths;
- autonomy/escalation policy.

After any drawing mutation, the previous review is stale. Render and inspect again.

## Self-review contract
A review should separately record:
- `subject_findings`: geometry/pose/proportion/weight observations;
- `exemplar_findings`: stage-grammar/abstraction/line-economy observations;
- `drawing_findings`: what the current artifact actually communicates;
- `corrections`;
- `remaining_concerns`;
- `decision = revise | advance`.

`advance` requires:
- no remaining concerns at the current stage's purpose;
- a concrete `advance_rationale`.

This is process integrity, not an automatic artistic score.

## Pre-draw observation lock

Before the first `stage_start()` or drawing action in a new run, create an
agent-authored `ObservationContract` with a typed `ViewObservation` and call
`DrawingRun.lock_observation()`. The lock records the subject reference hash,
observation id, digest, view/orientation, near-side role, arm visibility and
occlusion, and major prop overlap order.

The lock is semantic evidence, not automatic pose inference. It is immutable
through ordinary drawing mutations and is persisted in both
`observation/pre_draw_observation.json` and the resumable checkpoint. If the
observation changes after drawing starts, call `reopen_observation()`; the
runtime must reopen P1 and invalidate downstream drawing/review evidence rather
than silently changing the observation basis.

Legacy checkpoints without a lock remain readable, but they cannot start a new
stage or draw on the current branch until the worker explicitly reopens P1 and
creates a lock.

## Region envelope evidence

When a landmark axis looks plausible but a part is too thin, use the
agent-authored `RegionEnvelopeObservation` utility. Select the region axis
independently on the subject and drawing, record paired contour points at
increasing normalized stations (upper/mid/lower for an arm), visible fraction,
and occlusion. `compare_region_envelopes()` reports geometric discrepancy and
provenance integrity only; it is not an artistic score or stage decision. A
drawing profile must include its current drawing-state digest so stale evidence
cannot be reused after a correction.

At P3, process review and visual-fidelity review are separate artifacts. The
visual path writes a blind packet, an eight-region `RegionClosureManifest`, and
a `VisualFidelityReviewRecord`; only when both process and visual decisions are
advance may `DrawingRun.submit_stage_review(..., decision="advance")` advance
P3. Missing regions, blockers, revise decisions, lock mismatches, or stale
artifacts fail closed.

For side/three-quarter subjects, `TorsoOrientationObservation` keeps torso
orientation and near/far arm exposure explicit. A plausible torso width does not
cancel a wrong view label or a missing near-arm exposure.


## Subject-only reference policy
This repository intentionally ships no editable authoring or answer-image trees.
A fresh worker must not search for local answer drawings or copy from them. Use
the subject image, frozen StageContract, and verified prior drawing state as the
evidence chain.

The runtime package may retain representation-only reference metadata for
backward-compatible packet schemas. That internal data is not a task target,
does not supply coordinates, and must not replace fresh subject observation.


## Fresh-worker E2E Defect Closure
Dogfood testing proved autonomous P1→P3 closure but exposed operational friction and
premature visual closure risk.

Current protocol:
- `SKILL.md`, the package version, and worker packets always identify one consistent protocol;
- runnable benchmark case lives under `benchmarks/stage_reconstruction/full_body_croquis_subject_only/`;
- `submit_stage_review()` writes a resumable checkpoint automatically;
- resume with `DrawingRun.resume(output_dir)`;
- `finish(timelapse="auto")` persists authoritative outputs before bounded optional timelapse work;
- Agent-selected local review emits crop-registered overlay + raw difference evidence;
- worker packets include canvas-scale pencil visibility guidance;
- after carried concerns clear, perform a **fresh residual-mismatch sweep** before ADVANCE.

A previous concern list is memory, not the boundary of visual QA. If the residual
sweep finds a new stage-purpose mismatch, keep the stage at `REVISE`.

Read `references/review/fresh-worker-defect-closure.md`.

## Reopen Recovery
Later-stage evidence may invalidate an earlier CLOSED stage.

Use the **earliest responsible stage** rule:
- if a P3 mass must compensate for a wrong P2 axis, reopen P2;
- do not harden the compensating P3 shape.

`DrawingRun.reopen_stage()` performs branch-safe recovery:
- archives target/downstream review evidence;
- rewinds authoritative drawing history;
- prunes abandoned active action memory;
- clears target/downstream active reviews and local-review bindings;
- resets stage progress at the target;
- gives the target `reopen_restart / reopened_target`;
- gives invalidated downstream stages `reopen_restart / invalidated_downstream`.

Every invalidated downstream stage must be rebuilt and freshly reviewed after the
upstream fix. Archived reviews are evidence of the abandoned branch, not current truth.

Read `references/review/reopen-recovery.md`.

## P3 Hardening
P3 Primary Masses is dogfooded as an autonomous visual-hardening slice.

Preserve the closed P1/P2 structure, then build:
`head/hair → neck/ribcage → torso bridge → pelvis basin → tapered limb masses`.

Two important operating rules:

1. **Do not close on scripted concerns alone.**
   After each correction, re-observe the whole artifact. Direct visual QA can expose
   new egg/rail/connection failures even after the tracked concern list is empty.

2. **For clothed figures, avoid hidden-body bias.**
   Use observed clothing bulk as evidence for primary occupied mass, but omit
   folds/seams/final clothing contour.

P3 must not become egg + polygon + box + parallel-rail assembly.

Read `references/stages/p3-primary-masses.md`.

## P2 Hardening
P2 is dogfooded as a complete autonomous hardening slice.

Use the frozen P2 StageContract plus subject geometry, local review, and pass
memory. No local P2 answer image is required.

Recommended review order:
1. preserve the closed P1 gesture;
2. head cross-axis + shoulder tilt;
3. pelvis counter-tilt;
4. arm direction chains;
5. leg direction chains;
6. final axes-only contract check.

Do not introduce masses to make P2 look more complete. A sparse but correct axis
drawing is preferable to an over-developed P2.

P2 typically closes only after several revise/correct/re-review cycles:
`REVISE → corrections → fresh review → REVISE → corrections → fresh review → ADVANCE`.

Read `references/stages/p2-primary-axes.md`.

## Fresh P1 Regression
The canonical smoke is not sufficient evidence by itself. A fresh-worker regression
must independently re-author P1 on a different working canvas and still recover the
required hardening behavior.

The regression should use a working canvas different from the canonical
**368×576** canvas, and must not import or call the canonical smoke. Its trace
follows `schemas/fresh_p1_regression.schema.json`.

The regression must demonstrate:
- crown-origin dominant gesture;
- curved facial-centre direction;
- continuity through chin/neck/torso/pelvis/support leg;
- Agent-selected head and torso/pelvis local reviews;
- a real `REVISE`;
- an explicit correction action;
- pass-memory continuation with carried concerns;
- a fresh review;
- autonomous `ADVANCE` into P2 with no user gate.

This is a regression of P1 capability, not permission to copy the dogfood coordinates
into future subjects.

## Canonical Subject-Only Smoke
The official executable validation is:

`benchmarks/stage_reconstruction/full_body_croquis_subject_only/run_smoke.py`

A fresh worker should use this subject-only smoke as the canonical runtime check,
not import a pre-authored drawing or subject-coordinate heuristics.

It demonstrates:

`crown-origin P1 → prepare review → Agent-selected local reviews → REVISE →
explicit replace_stroke → fresh review → pass-memory continuation → ADVANCE`

Required properties of the canonical smoke:
- the dominant centre gesture begins at the crown, never at the neck;
- the facial-centre segment carries face direction before continuing through
  chin → neck → spine → pelvis → support leg;
- the first review is structured and records concrete remaining concerns;
- no legacy generic `observations=` review form is used;
- no user approval/input is requested between routine passes;
- pass 2 receives pass-1 `carried_concerns` and exact correction-action provenance;
- `advance` occurs only from a fresh review with `remaining_concerns=[]`;
- the example intentionally stops at `P2_primary_axes` rather than pretending the
  entire P1→P5 drawing is complete.

## Worker Pass Memory
The current stage does not reset mentally after every pass.

`prepare_stage_review()` emits `pass_memory.json` and embeds the same memory in
`worker_packet.json/md`.

For pass 2+, memory carries:
- previous review decision and digest;
- previous remaining concerns;
- previous Agent-reported corrections;
- exact drawing actions performed since that review;
- correction-action subset;
- concern/correction history.

The next pass starts by re-checking `carried_concerns`.

**Do not treat an edit as proof that a concern is resolved.**
The runtime records that a `replace_stroke`, `replace_segment`, erase, or delete
happened; only the Agent can decide from fresh rendered evidence whether it worked.

Each review record binds to its `pass_memory_digest` and `parent_review_digest`,
so the pass chain is reconstructable without user coaching.

Read `references/review/worker-pass-memory.md`.

## Agent-selected Local Review
When whole-view review leaves a concrete uncertainty, the worker should choose the ROI and call `DrawingRun.prepare_local_review()`.

```python
local = run.prepare_local_review(
    label="pelvis_legs",
    intent="Check pelvis-to-support transfer and counterbalance",
    subject_box=(...),
    drawing_box=(...),
    grammar_box=(...),
    # task_target_box=(...) only when the stage has a task target
)
```

The runtime must **not** detect anatomy or choose crop locations. It only validates the Agent-supplied boxes, creates exact crops/comparison boards, and binds them to the current drawing state/hash.

Useful local evidence should be linked with `local_review_ids` in `submit_stage_review()`.

After any drawing mutation, both the stage review and its local reviews are stale and must be regenerated.

Read `references/review/local-review-api.md`.

## P2 representation boundary
P2 workers may introduce only the axes listed by the frozen StageContract:
preserved P1 gesture, head cross-axis, shoulder/pelvis axes, major arm/leg
direction chains, and the major attached-object axis. Do not import a local
answer image to justify richer representation; record any contract uncertainty
and keep geometry subject-derived.

## Frozen Stage Contract
The current stage has a machine-readable `StageContract`.

`prepare_stage_review()` writes `stage_contract.json` beside the review artifacts and embeds the same contract in `worker_packet.json/md`.

The contract owns:
- `owns`: representation responsibilities introduced in this stage;
- `must_preserve`: earlier-stage information that may not drift;
- `allowed_representation`;
- `forbidden_representation`;
- `detail_ceiling`;
- `next_stage_unlocks`;
- `exemplar_contract.must_show / may_show / must_not_show`.

**The contract governs representation scope only. It is not an automatic artistic PASS/FAIL gate.**

Every structured review must include `contract_findings`.

### P2 boundary is frozen
P2 is primary axes only. Ribcage/pelvis mass contours, full limb thickness, hand/foot blocks, joint anatomy and clothing block-in belong downstream.

If any internal representation metadata appears richer than this contract, do
not expand P2. Record the contract mismatch in the stage review.

Read `references/stages/stage-contracts.md`.

## Reference authority
Before reviewing a stage, classify every image by role:

- `subject_reference`: geometry truth.
- `task_stage_target`: optional same-task/same-stage truth.
- `runtime_representation_hint`: optional representation-only guidance.
- `current_drawing`: the artifact being judged.

If a same-task stage target exists, the review priority is:

`task_stage_target > subject_reference > runtime_representation_hint`

Otherwise:

`subject_reference > runtime_representation_hint`

This does **not** allow a task target to override contradictory subject geometry,
and it never allows an internal representation hint to donate pose or coordinates.

Use:
```python
run = DrawingRun.create(
    "subject.png",
    "out",
    task_stage_targets={
        "P1_gesture": "same_subject_p1.png",
    },
)
```

Read `references/review/reference-authority.md` when a task provides stage-by-stage targets.

## P1 non-negotiable knowledge
For full-body gesture, the dominant centre gesture does **not** begin at the neck.
It begins at the **crown**, curves through the **facial centre** so unequal left/right head masses encode face direction, then continues through **chin → neck → spine → pelvis → support leg → weight landing point**.

Head envelope arcs, shoulder rhythm, pelvis rhythm and counterbalance leg are subordinate to this dominant path.

If the subject carries a large object that changes balance/silhouette, introduce its major axis early, but do not let it replace the body gesture.

## Failure recovery
- If a pass repeats the same mismatch, change observation strategy or crop; do not merely redraw the same guess.
- If a later stage reveals an earlier structural error, reopen the earliest responsible stage.
- If the drawing is cleaner but structurally wrong, reopen; do not polish the error.


## Stroke Weight / Line Hierarchy Calibration

When the dominant gesture is readable but all other structural lines are too faint,
do **not** keep a "dark centreline + ghost construction" hierarchy by default.

Preferred P1→P3 visual hierarchy:
- dominant gesture remains the reference stroke;
- primary axes and primary mass contours may approach roughly the same average width;
- their pressure/opacity can remain slightly lower than the gesture;
- cross-contours and minor construction remain subordinate;
- preserve within-stroke pressure variation, taper and graphite dynamics.

The important distinction is **average weight vs. expressive modulation**:
primary strokes may be nearly as thick as the centreline while still changing pressure
through the stroke. Do not flatten per-point pressure into a constant width/darkness.

`render.line_weight.calibrate_line_weight()` is a deterministic mechanical utility for
A/B review. It does not decide geometry and is not an automatic artistic judge.


## P3 Occupied-Volume Fidelity

Reopen P3 when fresh whole-view evidence shows that the mass abstraction is still too
narrow or too anatomical for the clothed subject.

Policy:
- use P1/P2 as inherited directional structure;
- use the subject as geometry/occupied-volume truth;
- use P3 grammar only for representation vocabulary;
- represent loose clothing as smooth primary occupied volume, not folds/details;
- use whole + local registered overlays to detect underfill/overshoot;
- if a P3 correction overshoots, revise P3 rather than reopening upstream without evidence;
- perform a fresh residual-mismatch sweep before ADVANCE.

Typical recovery sequence:
`P3 reopen → broad clothed torso/sleeves/legs → REVISE counter-leg overshoot → local correction → ADVANCE`.


## P1 Craniofacial Gesture / Head Envelope

A P1 head must not read as a polygon, badge, or generic closed egg.

If a smooth left/right pair still reconstructs a symbolic oval, use **segmented open
cranial construction**:
- one short crown arc;
- separate temporal→jaw arcs;
- visible gaps between crown and side arcs;
- one dominant curved crown→face→chin centre gesture.

The subject determines width, asymmetry and face turn. Do not use the outer hair
silhouette as a substitute for cranial direction. Hair volume belongs to P3.

If a later stage reveals the head still reads as a closed badge in isolation, reopen
P1 rather than patching the symptom downstream, and rebuild P2/P3 from the corrected
branch rather than resurrecting the old ones.


## P4 Structural Connections

P4 is not "add joint marks." It must explain how neighboring P3 masses connect.

Three failure modes must trigger revision:
- full-width elbow/knee lines that read as cardigan/jeans stripes;
- faceted mitten/diamond hand or foot polygons;
- ankle/hand blocks that look detached from the upstream limb mass.

Prefer:
- short clothing-aware directional planes where loose garments hide anatomy;
- smooth wrist→palm schematic blocks with no finger detail;
- smooth ankle→foot blocks with explicit landing direction;
- occluded partial hand blocks when the hand enters a pocket/waist overlap.

Before ADVANCE, inspect both whole view and local arm/hand + knee/foot crops.
If making a connection work requires moving an entire P3 mass, reopen P3 instead.


## P5 Clean Block-in / Construction Retirement

P5 begins with a **cleanup preflight**. If the subject's clean silhouette cannot be
drawn without contradicting P3/P4, reopen the earliest responsible stage before
cleaning.

P5 construction retirement is replayable:
- draw the verified decisive contour first;
- use `soft_lift` to subordinate redundant P1–P4 strokes;
- keep the dominant gesture only faintly when it still explains weight;
- do not raster-erase history merely for visual cleanliness.

Major clothing silhouette is allowed; micro folds, seams, texture, fingers, sneaker
panels and facial features remain outside the P5 clean-block-in ceiling.


## P5 Silhouette Separation

P5 cleanup must preserve **contour ownership**.

Do not weld two independent masses into one visually continuous contour.
When ownership changes because of overlap, use an explicit handoff:
- terminate the outer contour;
- leave a visible break / occlusion;
- continue the hidden/inside mass as an `overlap_contour` when needed.

Two independent strokes that come within a few pixels of each other and share a
near-parallel tangent can read as one continuous line after normal rendering, even
when the renderer performs no semantic merging.

`measure_contour_contact()` is evidence, not an automatic pass/fail rule.
The Agent still judges the subject's actual occlusion and semantic ownership.


## Fresh-worker E2E Test Protocol

A clean filesystem/subprocess in the same Agent conversation is **not** sufficient
evidence of fresh-worker autonomy. It can validate packaging and runtime behavior,
but the semantic worker still knows prior development context.

For a strict fresh-worker E2E:
- give a new worker/session only the packaged skill release and the task;
- do not provide prior dogfood reports, action IDs, coordinates or fixes;
- do not let the worker import `dev/dogfood/*` as a substitute for drawing;
- require the worker to discover the workflow from `SKILL.md` and its required
  reading route;
- return the complete run directory plus `DOGFOOD_REPORT.md` for independent audit.

`tools/audit_fresh_worker.py`, bundled inside the canonical skill folder, performs a
**mechanical evidence audit** on the returned run. It checks completion, stage
reviews, worker packets/pass memory, direct stroke history, final artifacts and
obvious reuse of historical dogfood action IDs. It does not replace visual/semantic
audit.

Runtime/review/session provenance comes from one version module, so `SKILL.md`, the
package version and worker packets never disagree about the current protocol. Scalar
finding strings normalize to one finding instead of individual characters.


## Subject-only Default

**One subject image is the normal operating mode.**

Do not assume that a user will provide P1/P2/P3/P4/P5 drawings of the same
subject. Those same-subject stage targets are optional and must only exist when
explicitly supplied through `task_stage_targets`.

In ordinary subject-only mode the authority is:

`subject_reference > frozen StageContract > verified prior drawing`

Any optional runtime representation hint decides only:
- stage abstraction vocabulary;
- construction convention;
- stroke economy / line hierarchy;
- detail ceiling.

They never decide the current subject's:
- pose;
- coordinates;
- proportions;
- perspective;
- subject-specific silhouette.

The worker creates a stage-specific working hypothesis from the subject itself,
renders it, then compares **subject ↔ current drawing**. The previous verified
stage is the structural prior for the next stage. No hidden target drawing is
required.

The canonical benchmark `benchmarks/stage_reconstruction/full_body_croquis_subject_only/`
intentionally contains only the subject image + metadata/smoke runner and covers
P1→P5.

Successful `stage_start`, `draw`, `draw_many`, and `prepare_stage_review` calls
atomically persist resumable state.

A same-subject `task_stage_target` remains supported as optional extra evidence,
but the worker must never become dependent on it.


## Large Attached-object Topology

A large prop or attached object is not allowed to survive P5 as a generic pair of rails
when the subject visibly contains major subpart topology.

Use the already-verified object axis/extent as a structural prior, then state only the
largest subject-derived topology changes: width transitions, dominant subparts, large
openings and attachment/overlap.

This rule is generic to long tools, bags with major attachments, instruments, shields,
large accessories and other silhouette-changing props.

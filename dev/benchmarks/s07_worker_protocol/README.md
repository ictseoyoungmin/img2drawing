# S07 isolated worker comparison — preparation contract

This is a preparation tool, **not** a drawing model, worker runner, artistic judge, or release gate.

Run `python dev/tools/prepare_s07_blind_workers.py --help`. Supply one private PNG reference, one goal Markdown, one JSON budget with `canvas`, `supersample`, `max_actions` and `max_wall_sec`, `worker_model` and `max_tokens`, plus the two pinned wheel/skill ZIP pairs. Expected wheel SHA-256 values are mandatory. This tool does **not** fetch releases, install packages, upload reference files or access repository source at worker time.

It produces `workers/<opaque-code>/` containing precisely `reference.png`, `goal.md`, `budget.json`, `skill.zip`, `worker.json` and the wheel under its original valid filename, plus a separate `evaluator_only.json` with the randomized medium mapping. Install the wheel named by `worker.json.runtime_filename`; never rename it to `runtime.whl`. Sealed reference, skill and runtime copies must match their recorded input hashes. The evaluator must also verify each skill ZIP against the intended published asset or tracked package build before sealing; a locally recorded hash alone does not authenticate its origin. Output creation refuses an existing destination, including one appearing during preparation. Copying into the exclusively created destination is not atomic; consumers must wait for successful completion.

**Never send the evaluator file to either worker or the blinded reviewer.** Workers require separate fresh contexts, exactly the supplied inputs, the same base goal/budget/reference and their own pinned runtime. The medium-specific sentence intentionally differs to authorize the relevant materials. The production skill ZIP contains runtime source for installation; workers may read only `img2drawing/SKILL.md`, `img2drawing/README.txt` and Markdown under `img2drawing/references/`, as declared in `worker.json.allowed_skill_reads`. They may install the wheel and use public runtime discovery and APIs, but must not read `src/`, installed implementation source, example/session files, other workers' files, repository files or prior evaluator feedback. The executor must enforce and audit this read boundary; this preparation tool does not provide OS/filesystem isolation. Do not provide prior sessions, extracted coordinates, prior pictures or example answers.

After independent runs, mechanically verify resumed checkpoints, observation/action provenance, current PNG, end-to-end GIF and final hashes before blind whole-image and region/crop assessment (face/eyes/expression, hair masses, hands/contact, silhouette and occlusion, line hierarchy, black-white and tone decisions). Keep evaluator-authored residual cause (geometry vs material) and verdict (accept/tie/reject). Worker preparation or mechanical PASS **never** means artistic PASS. Separately compare matched authored paths under graphite/ink; areas and tones are novel material tests, not same-appearance equivalents. Avoid uploading reference/session or derived geometry to Git.

Requires an external fresh agent executor and human/independent visual reviewer. S07 remains NOT_RUN until those artifacts exist. The tool accepts PNG IHDR identity only; it does not inspect image meaning or render pixels.

## Controlled material probe

Run `material_probe.py --medium graphite --out <new-directory>` with the pinned v1.3.0 wheel, then `--medium ink` and `--medium capabilities` in the candidate wheel environment. Use the same Python/NumPy/Pillow environment for both. The paired modes share eight explicit paths (328 points), pressure samples and nominal maximum widths; pressure changes graphite deposition and pen diameter differently, so this is not an equal-appearance or speed benchmark. The separate capability panel tests authored black areas, interior reserves, white overpaint, three dot densities and a gradient. It has no graphite-equivalent geometry claim.

Each run asserts resumed final pixel equality, action-0/latest replay endpoints, final pixel identity and decoded GIF tolerance. The compact `measured_material.json` records the measured identities; private drawing inputs and generated images stay outside Git. Visual review remains separate from these mechanical assertions.

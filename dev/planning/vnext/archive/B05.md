## Responsibility

Make a fresh worker start a figure with a readable whole-pose construction:

`read pose → line of action → head/ribcage/pelvis mass → balance/plumb → joints/limbs`

This is a skill-side authoring grammar over the stage-free `DrawingSession`. It is
not a runtime stage machine, and its construction phase labels are drawing
vocabulary only.

## Delivered

- `PoseObservation`, `ConstructionMark`, and `InitialConstruct` value objects.
- `author_initial_construct()` records observation first and commits the authored
  marks through the existing atomic `DrawingSession.draw_many()` path.
- `inspect_initial_construct()` reuses the existing `DrawingSession.inspect()` and
  inspection implementation.
- Initial construct validation keeps phase membership, geometry, and unique IDs,
  but does not impose a phase progression order. Agent-authored tuple order is
  preserved, including interleaved phase labels.
- Subject-only B05 dogfood with explicit x/y/z hypothesis for the turned head,
  back/side torso, near/right arm, far/left elbow, balance, legs, feet, and prop.
- No joint circles, second renderer, second inspection path, manifest, or runtime
  advancement gate was added.

## Frozen contracts

- B04 remains the one-history and checkpoint authority.
- Construction phase names describe drawing intent only. They are not public stage
  state, progression gates, manifests, or advancement conditions.
- Canonical dogfood receives the subject reference plus drawing mode/skill only.
  `ideal-stroke-reference.png` is a capability exemplar and is not loaded by the
  runner.
- Macro correctness is judged from subject versus current drawing: pose turn,
  line of action, masses, balance, depth-aware limbs, and prop overlap.

# B06 Context Capsule — Residual-driven correction

## Purpose

B06 replaces stage reopen semantics with an Agent-owned correction loop over the
existing vNext `DrawingSession` and B02+B03 `InspectionSheet` boundary:

```text
inspect A → choose one residual → explicit history edit → inspect B → keep/revise
```

The runtime does not rank residuals, score visual quality, or add a lifecycle gate. The
Agent chooses the highest-impact observed mismatch and decides whether fresh visual
evidence improved it.

## Public surface

Import from `img2drawing.vnext` or the root package:

```python
from img2drawing import CorrectionRecord, DrawingSession, ResidualRecord
```

`DrawingSession.record_residual()` accepts a `ResidualRecord` or keyword fields:

- `observation_id`, `observation`, `scope`, `severity`, `impact_rationale`;
- `responsible_premise`, `responsible_stroke_ids`, `planned_edit`;
- `before_inspection_id` (the session derives the matching before digest and current
  history cursor for keyword calls).

The method rejects unknown observations, non-current before evidence, duplicate IDs, and
non-open records. The residual remains compact and human-authored.

Use existing `replace_stroke`, `replace_segment`, `soft_lift`, `delete_stroke`, or
`draw` actions for the edit. `record_correction()` binds one or more explicit history
actions to a current `after_inspection_id` and requires a changed drawing digest:

- `decision="keep"` records fresh evidence and marks the residual resolved;
- `decision="revise"` records the attempt but leaves the residual open for another loop.

Callers may identify an edit by its history action ID or generated stroke ID; the record
stores the canonical history action ID. Observation IDs must match the residual (or the
neutral `vnext-unobserved` marker), and actions before the residual cursor are rejected.

## Persistence and safety

Session checkpoints remain schema `img2drawing.vnext.session.v2` and now carry
`residuals` and `corrections` arrays. Writes use the existing atomic checkpoint path.
Resume validates:

- record schema and unique residual/correction IDs;
- residual observation and before/after inspection digest bindings;
- correction observation/residual links and inspection digests;
- action existence, observation provenance, and history cursor ordering.

No `current_stage`, `advance`, `close`, `reopen`, duplicate history, renderer, or
inspection implementation was introduced. Legacy stage runtime and persistence remain
compatibility material for B12/B18.

## Responsibility

Freeze the vNext contract boundary between stage-free drawing capabilities and
the frozen R23 stage/review workflow. B01 created no runtime, API, or review-schema
implementation.

## Canonical lifecycle

```text
create → observe → draw → inspect → correct → repeat → finish
```

The lifecycle is stage-free. `draw()` and `correct()` do not require or branch on
`P1`–`P6`. `inspect()` is read-only, current-state-bound, and does not create a
stage manifest or visual PASS decision. The Agent owns observation, mismatch
prioritization, correction choice, and visual acceptance.

## State and ownership

- `DrawingSession` owns session identity/metadata and one authoritative history.
- History owns authored actions, current cursor/state, and correction provenance.
- `StrokeIR` is the read-only current-state geometry projection.
- Canvas/render/replay/inspection consume snapshots and do not rewrite geometry.
- Subject identity and hash remain geometry/evidence anchors.

## Disposition

- **Reuse unchanged:** `StrokeIR`, persisted `DrawingSession` as an internal
  persistence primitive, transaction helper, renderer profiles, cursor replay,
  `ObservationContract`, `SubjectReference`, and generic artifact/hash/compare
  helpers.
- **Extract stage-free portion:** `Stroke`, `AgentDrawingSession`, `CanvasHistory`,
  `CanvasRuntime`, `CanvasInspector`, pencil material renderer, cursor/action
  timelapse export, and action memory.
- **Legacy-wrap:** `DrawingAction`, `CanvasEditor`, `DrawingRun`, R23 checkpoint/
  resume, stage-bound observation/reference records, local/reference reviews,
  pass memory, manifests, worker packets, reopen machinery, and stage guidance.
- **Retire from the vNext main path:** `StageProgress` and the mandatory stage
  registry/state-machine authority.

The complete file/line evidence and dependency graph are in the archived B01 card.

## Frozen invariants

- One shared capability path; R23 and vNext are not co-equal production trees.
- Legacy stage labels may survive only as opaque compatibility provenance.
- Corrections append explicit stroke/segment edits; stage reopen bookkeeping is not
  a vNext lifecycle requirement.
- Checkpoints bind subject identity, history/action state, current-state digest,
  renderer identity/version, and portable artifact references. R23 progress,
  stage registry, review manifests, and reopen maps are adapter-only.
- Replay is cursor/history based and renderer-deterministic; stage/critic timelapse
  modes remain legacy compatibility behavior.

## Known limitations

- No stage-free runtime implementation exists yet.
- The vNext checkpoint and inspection shapes are contract skeletons, not schemas
  or runtime machinery.
- Existing R23 tests continue to validate the legacy path only; they are not vNext
  PASS evidence.

## Reopen conditions

- A vNext public operation gains a required P1–P6 branch or stage gate.
- Runtime begins judging visual correctness or choosing the highest-impact mismatch.
- A second co-equal core/session/renderer tree is introduced.
- Legacy review/checkpoint artifacts are promoted to vNext PASS evidence.
- A later implementation contradicts the recorded state ownership or dependency
  direction without a new contract decision.

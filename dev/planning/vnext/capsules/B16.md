# B16 Context Capsule — Agent authoring and editing ergonomics

Status: **CLOSED**

## Purpose

B16 makes long correction histories navigable without adding an ownership lifecycle,
parallel edit history, or persisted index. The existing `CanvasHistory` remains the only
drawing truth and every mutation still crosses the atomic `DrawingSession` checkpoint
boundary.

## Derived authored-element surface

`session.authored_elements()` rebuilds immutable `AuthoredElement` records from actions up
to the current cursor and filters them by:

```text
stroke/fill type · current/superseded/deleted status · part · role
action id · observation id
```

Each record includes creation/latest action sequence, all related action/observation ids,
latest action kind/reason, revision count, and explicit whole-stroke `superseded_by`.
Generated fill hatch/contact strokes are render products and never appear as authored
decisions.

`resolve_authored_element()` follows replacement ancestry to the current stroke or returns
`None` after deletion. `current_stroke()` returns a detached current stroke and
`current_fill_region()` returns the latest stable fill definition. Ambiguous cross-type ids
require an explicit element type.

## Bounded context and edit safety

`authoring_summary(limit, part, role)` returns current counts, open residual ids, a bounded
element list, truncation, history cursor, and drawing-state hash. It is recomputed on every
call and is deliberately absent from checkpoints.

History now rejects reused stroke identities and validates current existence before
soft-lift or hard deletion, closing orphan and stale-target holes. Whole replacement and
segment edits already validate their targets. Transaction rollback leaves no partial
action or checkpoint after rejection.

## Consolidated fill revision

`DrawingSession.replace_fill_region()` is the single public implementation beside the
necessary low-level history action. The historical root
`replace_fill_region(session, ...)` function is now a compatibility delegate with no
private history access. Stroke and fill queries therefore share part, role, action,
observation, reason, and revision provenance semantics.

## Evidence

- Focused editing/correction/fill/session/rendering regression: 60 passed.
- Complete development regression: 206 passed with five pre-existing JSON-schema
  metaschema deprecation warnings.
- The deterministic fixture locates a thin near-arm premise, replaces it with a thicker
  current contour, revises one coat value region, binds fresh correction evidence, rejects
  a stale edit without cursor movement, renders, resumes, and reproduces the same summary.
- Contract review confirms one fill orchestration implementation, no checkpointed index,
  no render dependency in navigation, and no edit-session/ownership-stage/history fork.
- Canonical English guidance routes long-history navigation to one new reference and value
  revision to the session method; legacy R23 `CanvasEditor` remains isolated compatibility
  material rather than a vNext route.

This proves mechanical editing ergonomics. D01–D05 after B18 own real long-run authoring
usability and visual correction quality.

## Reopen conditions

Reopen B16 if current/superseded identity becomes ambiguous, orphan edits enter history,
fill and stroke provenance diverge, summaries persist as competing truth, generated
contacts appear as authored decisions, or a new edit/session/ownership lifecycle emerges.

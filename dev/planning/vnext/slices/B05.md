# B05 planned reopen — Canonical Pn guidance de-anchoring

Formal state: **CLOSED / NEXT REOPEN**
Activation: pending; this must be the next production task
Existing closure: `../capsules/B05.md`

## Reopen record

### Reason and trigger

B05 construction implementation and visual dogfood are closed, but the universal
drawing plan requires a normal reading route that does not teach P1–P6 orchestration.
The current `skills/img2drawing/SKILL.md` still contains substantial stage review,
stage handoff, advance/reopen, and Pn detail, and it routes legacy references from the
same top-level document. This attention leak would pull tonal/free-draw work back into
the croquis stage model.

### Affected contract surface

- `skills/img2drawing/SKILL.md` normal reading route and mission wording
- `skills/img2drawing/references/INDEX.md`
- stage-coupled playbooks, review guidance, examples, and package description
- drawing knowledge currently trapped in `references/stages/p1-*.md` through `p6-*.md`
- explicit legacy R23 documentation entry point

Runtime stage/persistence removal is not part of this reopen.

### Migration risk

- useful gesture, mass, balance, overlap, feet, prop, identity, and accent guidance may
  be lost while removing lifecycle language;
- existing R23 continuation users may lose their compatibility instructions;
- moving paths can leave broken links or silently duplicate canonical guidance;
- broad cleanup can accidentally expand into B12/B18 runtime retirement.

## Goal

A new drawing worker reads one short stage-free route, learns an ordered but non-gated
drawing grammar, and reaches the existing B04/B05 API without encountering Pn. A legacy
R23 continuation remains possible only through one clearly labeled compatibility link.

## Deliverables

1. Rewrite the canonical `SKILL.md` around observe → construct/draw → inspect → correct
   → finish; remove the current top-level “stage handoff/review” instruction blocks.
2. Create a stage-free reference taxonomy for construction, observation, resolution,
   finish, mode, and residual review guidance.
3. Extract reusable knowledge from P1–P6 before moving or labeling the old documents as
   legacy; do not copy stage ownership/advance/manifest semantics.
4. Make `references/INDEX.md`, the example, package description, and canonical links
   point to vNext-native guidance.
5. Preserve one explicit `legacy/r23` (or equivalently isolated) entry with migration
   notes for existing `DrawingRun` continuations.
6. Add a deterministic link/route audit and record a subject-only fresh-worker reading
   route check.
7. Reclose B05 with an updated capsule; preserve the existing construction evidence.

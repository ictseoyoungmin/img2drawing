# B16 — Agent authoring and editing ergonomics

State: **CLOSED**
Depends: B15

## Goal

Make the canonical stage-free drawing surface practical for long correction-heavy runs.
The Agent should be able to find, understand, and repair responsible authored marks
without reaching into legacy internals or creating a second ownership/lifecycle system.

## Existing primitives to preserve

The project already has or is expected to have explicit history-safe operations such as:

```text
draw / draw_many
replace_stroke / replace_segment
soft_lift / soft_lift_segment
delete
fill_region / replace_fill_region
```

B16 should improve discoverability/composition around these primitives before inventing
new mutation types.

## Candidate ergonomics surface

Only add helpers justified by concrete authoring friction, for example:

- query current/live strokes/actions by `part`, `role`, provenance, action id, fill id;
- resolve superseded/retired marks to the current authored representation;
- inspect responsible stroke/action context before editing;
- bounded local edit helpers that preserve append-only history;
- region/fill identity lookup;
- cursor/history summaries for the Agent without dumping the whole session;
- small edit transaction helpers where atomic multi-action mutation is already required.

These are navigation/edit ergonomics, not a new runtime architecture.

## Representation principle

Prefer **one artistic decision → one compact authored action** when the representation
supports it. Generated deterministic contacts may expand at render/replay time, but
machine-generated microstrokes must not silently become hundreds of authored decisions.

Do not optimize JSON line count in isolation. Session compaction is acceptable only when
it preserves explicit authored intent, deterministic replay, correction provenance, and
visual output.

## Deliverables

- focused query/navigation API for live authored representation;
- explicit current/superseded identity semantics for strokes/regions/actions;
- helpers for local corrections that remain checkpoint/replay/resume safe;
- compact session/context summaries for workers where justified;
- duplicate/orphan/stale edit regression tests;
- documentation that keeps `part`, `role`, provenance, and history as the existing
  responsibility vocabulary rather than adding a new ownership lifecycle;
- B16 capsule and status transition to B17.

## Definition of Closed

- [x] A worker can locate the current responsible mark/region without parsing legacy stage
      structures or manually walking the entire JSON session.
- [x] Local edit helpers append explicit replayable mutations and preserve authoritative
      history.
- [x] Superseded/retired identities cannot be mistaken for current representation.
- [x] Value-region revision and ordinary stroke correction share consistent provenance
      lookup semantics.
- [x] No new ownership state machine, lifecycle cursor, or parallel edit history exists.
- [x] Session/context summaries do not become a second source of truth.
- [x] Technical fixtures cover mutation/resume/orphan/stale behavior; real long-run
      usability is deferred to D01–D05 after B18.
- [x] Capsule/docs/tests complete and B17 is next sole WIP.

## Non-goals

Automatic edit planning, artistic residual selection, editor GUI, large compression
rewrite without measured need, and fresh dogfood.

# B11 — Canonical RenderProfile, replay, and GIF parity

State: **SKELETON**
Depends: B10

## Goal

Bind final PNG, replay, and timelapse to one canonical rendering configuration and
history so exported process and final output cannot silently drift.

## Deliverables

- versioned `RenderProfile` contract for renderer/material/paper/compositing,
  supersampling, size, and seed domain;
- canonical vNext cursor replay and action0-to-latest GIF export;
- parity manifests and regression fixtures;
- explicit unsupported/migration behavior for legacy renderer profiles.

## Definition of Closed

- [ ] A history with more than one action yields more than one meaningful GIF frame.
- [ ] Action 0 and latest state are included with documented timing semantics.
- [ ] Final GIF frame and canonical final render have pixel-equivalent output under the
      same profile, or a documented encoded-color tolerance.
- [ ] Replay/resume are deterministic for the same history/profile/version.
- [ ] Silent supersample, material, seed, or canvas drift is rejected.
- [ ] Existing pencil-contact renderer stays single-source; no geometry mutation occurs.
- [ ] Unit/E2E regression, artifact provenance, performance/size budget, and capsule pass.

## Non-goals

Large brush catalogs, charcoal/ink implementation without dogfood evidence, and legacy
runtime removal.

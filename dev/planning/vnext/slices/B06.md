# B06 — Residual-driven correction

State: **CLOSED**
Depends: B05 reclosed

Activated: **2026-08-31** as the sole production WIP after B05 reclosure and the
R23 compatibility release-gate fix. The implementation is limited to residual and
correction provenance over the existing `DrawingSession`/`InspectionSheet` boundary.
No later slice is active; B07 remains a skeleton pending explicit activation.

## Goal

Replace stage reopen semantics with a reusable loop that finds the current
highest-impact observed mismatch, identifies its responsible premise/strokes, edits the
authoritative history, and proves improvement through a fresh inspection.

## Deliverables

- compact residual record: observation, scope, severity/impact rationale, responsible
  premise/stroke IDs, planned edit, before/after evidence references;
- global and local correction path using existing replace/soft-lift/delete/draw actions;
- lightweight correction memory that prevents stale concern reuse without becoming a
  gate machine;
- one B05 subject correction fixture covering premise-level and local repair;
- resume-safe correction provenance.

## Definition of Closed

- [x] `inspect A → choose residual → edit → inspect B` is executable through the real
      `DrawingSession`/`InspectionSheet` boundary.
- [x] Every correction references the state and observation it judged; stale evidence
      is rejected or visibly invalidated.
- [x] At least one local edit and one premise/global reconstruction preserve full history.
- [x] Direct side-by-side review shows material visual improvement; edit count alone is
      not accepted as proof.
- [x] The Agent, not runtime metrics, selects priority and acceptance.
- [x] No `current_stage`, advance/close/reopen lifecycle, duplicate history, renderer,
      or inspection path is introduced.
- [x] Focused/full tests, checkpoint/resume, duplicate/orphan audit, and capsule pass.

## Closure record

Closed: **2026-08-31**.

- `ResidualRecord` and `CorrectionRecord` are public vNext records with portable
  checkpoint persistence. Before/after inspection hashes and observation IDs are
  required; `keep` resolves and `revise` leaves a residual open.

  preserving the canonical history action ID. It rejects stale after evidence, action

  repair and local segment repair. Committed sheets and trace are in

  the resumed validator checks residual, observation, inspection, digest, action, and
  cursor bindings before accepting persisted correction memory.

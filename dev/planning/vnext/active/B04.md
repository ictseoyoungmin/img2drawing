## Reason and triggering evidence

Repeated `inspect()` calls overwrite the same `inspection/` directory. History
then contains multiple records pointing at one mutable manifest, so an earlier
inspection cannot be reproduced. If checkpoint persistence fails after the
second render, in-memory history rolls back while disk contains the second
state. This breaks inspection continuity and provenance binding.

## Affected contract

- Inspection history must refer to immutable, unique artifact directories.
- A failed inspection checkpoint must not leave a new committed artifact directory.
- Resume must preserve every prior inspection record and its bytes.
- Observation IDs must be unique and drawing actions may reference only known
  observations, except the documented `vnext-unobserved` default.
- `checkpoint(custom_path)` must serialize the actual checkpoint filename.

## Migration risk

Existing callers may expect `output_dir/inspection/` as the single output path.
The vNext normal path will migrate to `output_dir/inspections/000001/` and retain
only unique, append-only directories. Existing R23 and standalone B02+B03 paths
are not changed.
